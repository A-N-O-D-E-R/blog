# Building Jmachine: A Multi-Agent AI Workflow Orchestrator in Java Spring Boot

## From TypeScript to Enterprise Java: A Port Story

What happens when you take a modern TypeScript AI workflow orchestrator and rebuild it from scratch in Java Spring Boot? You get **Jmachine** — a production-ready, enterprise-grade multi-agent orchestration framework that brings the power of coordinated AI agents to the JVM ecosystem.

This is the story of building Jmachine: from initial design decisions through advanced features like loop-on-failure, conditional execution, and MCP protocol integration, all backed by a comprehensive test suite with 92% pass rate.

---

## The Problem: AI Agent Chaos

Modern AI coding workflows involve multiple specialized agents working together:
- One agent generates code
- Another validates it
- A third fixes issues
- A fourth runs tests
- A fifth handles deployment

Without orchestration, this becomes chaos:
- **No coordination**: Agents don't know when to run or what to pass to the next agent
- **No resilience**: One failure stops the entire workflow
- **No observability**: You can't see what's happening in real-time
- **No recovery**: Crash means starting over from scratch

Sound familiar? That's where Jmachine comes in.

## Feature Deep Dive

### 1. Loop on Failure: Smart Retries

When a validation step fails, automatically loop back to the fixer:

```java
public class LoopManager {
    public boolean shouldLoop(int stepIndex, ModuleStep step) {
        if (step.loopSteps() == null || step.loopSteps() <= 0) 
            return false;
            
        int attempts = loopAttempts.getOrDefault(stepIndex, 0);
        int maxIterations = step.loopMaxIterations() != null ? 
            step.loopMaxIterations() : DEFAULT_MAX_ITERATIONS;
            
        return attempts < maxIterations;
    }
    
    public int calculateLoopTarget(int currentIndex, int loopSteps) {
        return Math.max(0, currentIndex - loopSteps);
    }
}
```

**Execution flow:**
1. Generator creates code
2. Validator checks → fails
3. Loop back 2 steps to fixer
4. Fixer attempts fix
5. Validator runs again
6. Repeat up to 3 times
7. Give up gracefully after max attempts

**Use cases:**
- Code generation + validation loops
- Build + fix cycles  
- Test + debug iterations
- Optimization + verification

### 2. Conditional Execution: Smart Branching

Run steps only when conditions match:

```json
{
  "agentId": "deployer",
  "conditions": ["tests_passed", "env=production"]
}
```

```java
public class ConditionEvaluator {
    public boolean shouldExecute(List<String> conditions, 
                                  Map<String, Object> context) {
        if (conditions == null || conditions.isEmpty()) 
            return true;
            
        for (String condition : conditions) {
            if (!evaluateCondition(condition, context)) 
                return false;
        }
        return true; // AND logic
    }
    
    private boolean evaluateCondition(String condition, 
                                      Map<String, Object> context) {
        // NOT operator
        if (condition.startsWith("!")) {
            String varName = condition.substring(1);
            return !isTruthy(context.get(varName));
        }
        
        // Equality check
        if (condition.contains("=")) {
            String[] parts = condition.split("=", 2);
            return Objects.equals(context.get(parts[0]), parts[1]);
        }
        
        // Variable existence
        return isTruthy(context.get(condition));
    }
}
```

**Predefined conditions:**
- `tests_failed`, `tests_passed`
- `build_failed`, `build_succeeded`  
- `has_errors`, `no_errors`

**Custom conditions:**
- Variable existence: `production`
- NOT operator: `!debug_mode`
- Equality: `env=production`

### 4. MCP Integration: Lifecycle Management

Model Context Protocol support for per-agent environment setup/cleanup:

```json
{
  "agentId": "docker-builder",
  "mcp": {
    "enabled": true,
    "setupCommand": "docker network create test-network || true",
    "cleanupCommand": "docker network rm test-network || true",
    "environment": {
      "DOCKER_BUILDKIT": "1"
    },
    "workingDirectory": "/tmp/build"
  }
}
```

```java
@Service
public class MCPService {
    public MCPResult executeSetup(MCPConfig config) {
        ProcessBuilder pb = new ProcessBuilder("/bin/sh", "-c", 
                                               config.setupCommand());
        pb.directory(new File(config.workingDirectory()));
        
        Map<String, String> env = pb.environment();
        env.putAll(config.environment());
        
        Process process = pb.start();
        boolean finished = process.waitFor(60, TimeUnit.SECONDS);
        
        return finished && process.exitValue() == 0 ?
            MCPResult.success(MCPPhase.SETUP, output) :
            MCPResult.failure(MCPPhase.SETUP, error, exitCode);
    }
}
```

**Lifecycle:**
1. Setup before agent execution
2. Agent runs with LLM
3. Cleanup after (even on failure)

**Use cases:**
- Docker container management
- Database setup/teardown
- API mock server lifecycle
- Resource provisioning

## Implementation Journey

### Challenge 1: For-Each vs Manual Index Control

**Problem**: Loop-on-failure requires jumping back N steps, but Java for-each doesn't allow index manipulation.

**Initial attempt:**
```java
for (WorkflowStep step : steps) {
    // Can't loop back!
}
```

**Solution**: Manual for-loop with controlled index:
```java
for (int i = startStepIndex; i < steps.size(); ) {
    ModuleStep step = (ModuleStep) steps.get(i);
    AgentResult result = executeAgent(step);
    
    if (result.success()) {
        loopManager.resetLoopCounter(i);
        i++; // Move forward
    } else if (loopManager.shouldLoop(i, step)) {
        loopManager.recordLoopAttempt(i);
        int loopTarget = loopManager.calculateLoopTarget(i, step.loopSteps());
        i = loopTarget; // Jump back!
    } else {
        i++; // Give up, continue
    }
}
```

### Challenge 2: Jackson Polymorphic Deserialization

**Problem**: Workflow has 3 step types (module, separator, coordination) in single array.

**Solution**: Sealed interfaces + `@JsonSubTypes`:
```java
@JsonTypeInfo(use = JsonTypeInfo.Id.NAME, property = "type")
@JsonSubTypes({
    @JsonSubTypes.Type(value = ModuleStep.class, name = "module"),
    @JsonSubTypes.Type(value = SeparatorStep.class, name = "separator"),
    @JsonSubTypes.Type(value = CoordinationStep.class, name = "coordination")
})
public sealed interface WorkflowStep 
    permits ModuleStep, SeparatorStep, CoordinationStep {}
```

Now Jackson automatically deserializes based on `"type"` field.

### Challenge 3: Test State Persistence

**Problem**: Tests expect fresh state, but FileStateRepository persists across test methods.

**Solution**: JUnit 5 `@TempDir` with per-test isolation:
```java
class WorkflowStateManagerTest {
    @TempDir
    Path tempDir;
    
    @BeforeEach
    void setUp() {
        ObjectMapper mapper = new ObjectMapper();
        repository = new FileStateRepository(mapper, tempDir.toString());
        manager = new WorkflowStateManager(repository);
    }
    
    @Test
    void testStatePersistence() {
        manager.initializeWorkflow("wf1", "Test", "/path", 3);
        manager.recordStepCompleted(0, "step-0", "s1", true, "out", 100);
        
        WorkflowState loaded = repository.load();
        assertEquals(1, loaded.getCurrentStepIndex());
    }
}
```

Each test gets isolated temp directory, no cross-contamination.

### Challenge 4: Jackson Getter Serialization

**Problem**: `isResumable()` method serialized as `"resumable": true`, but can't deserialize (no setter).

**Error:**
```
UnrecognizedPropertyException: Unrecognized field "resumable"
```

**Solution**: `@JsonIgnore` on computed property:
```java
public class WorkflowState {
    @JsonIgnore
    public boolean isResumable() {
        return completedAt == null && currentStepIndex < totalSteps;
    }
}
```

Computed at runtime, not persisted.

### 1. Spring AI Was The Right Choice

**Pros:**
- Portable across providers (switched from Bedrock to OpenAI in 5 minutes)
- Streaming just works via Reactor
- Built-in retry and error handling

**Cons:**

**Verdict:** 9/10, would use again

### 2. Sealed Interfaces + Records = ❤️

Java 17 features made type-safe workflow steps elegant:

```java
public sealed interface WorkflowStep 
    permits ModuleStep, SeparatorStep, CoordinationStep {}

public record ModuleStep(
    String agentId,
    String promptPath,
    Integer loopSteps,
    List<String> conditions
```

**Benefits:**
- Exhaustive pattern matching
- Jackson polymorphic deserialization
- Immutability by default
